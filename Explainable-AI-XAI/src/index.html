Single-Layer, Single-Head Self-Attention

A miniature transformer encoder block. Type a short sentence, then step through tokenization, embedding, positional encoding, and the scaled-dot-product attention head.

Current: Not Started
Step 1 — Tokenize

Split the sentence into word-level tokens, then map each token to an integer ID using a small built vocabulary V.

Step 2 — Token Embedding

Look up each token ID in the embedding matrix E ∈ ℝ|V| × d. This turns each integer into a continuous vector of dimension dmodel.

Step 3 — Add Sinusoidal Positional Encoding

Without positions, attention is permutation-invariant. Inject order with a fixed sinusoid:

Step 4 — Project to Queries, Keys, Values

Three learned linear projections of the input. Each token vector becomes three new vectors of dimension d.

Step 5 — Scaled Dot-Product Scores

Score every (query, key) pair. The 1/√d scaling keeps gradients well-conditioned for larger dimensions.

Step 6 — Row-wise Softmax

Turn each row of scores into a probability distribution over keys.

Step 7 — Attention Output

Each token's output is a weighted average of value vectors, weighted by how much it attended to each key.

Step 8 — Add & Norm (1)

Residual connection lets gradients flow around the attention layer. LayerNorm then standardises each row to zero mean / unit variance, which keeps deeper stacks from drifting.

Step 9 — Position-wise Feed-Forward

The same 2-layer MLP is applied to every token independently. The non-linearity (ReLU) is what gives the transformer its expressive power beyond linear attention.

Step 10 — Add & Norm (2)

Same pattern again: residual around the FFN, then LayerNorm. The result is the block output that would feed into the next transformer block in a deeper model.

Step 11 — Output Projection

Project every token's final hidden vector onto the vocabulary. Each column of Wout defines the “direction” for one word.

Step 12 — Predict Next Word

A decoder-style head: take the last token's logits, softmax over the vocabulary, and the argmax is the predicted next word.

Retrieval-Augmented Generation

A minimal RAG pipeline using TF–IDF retrieval. Edit the corpus, enter a query, and watch the system tokenize, build vectors, compute similarities, and assemble a prompt with retrieved context.

Step 1 — Tokenize Corpus + Query

Lowercase, strip punctuation, split on whitespace. Each document becomes a bag of tokens.

Step 2 — Build Vocabulary and IDF

Inverse document frequency penalises terms that appear in many documents. Rare-but-recurring terms get the highest weight.

Step 3 — TF–IDF Matrix

For every document, weight its term frequency by the IDF of each term.

Step 4 — Query Vector

Encode the query in the same TF–IDF space so we can compare apples to apples.

Step 5 — Cosine Similarity

Compare query to each document by the angle between their TF–IDF vectors.

Step 6 — Top-k Retrieval

Keep the k most-similar documents to feed to the generator.

Step 7 — Augmented Prompt

Concatenate retrieved context and the query into the prompt that would be passed to a generator.
